# 03 · 去开机广告

这台电视的开机广告**不在 /system 里，而在 /data 里**，且由一个叫 `advert` 的原生守护进程播放。
所以「删系统 APK」的思路对它无效，正确做法是**断开关 + 清素材**。

## 1. 逆向出的广告链路

```
init.rc 里：
  service advert /system/bin/advert
      class main
      user root
      group graphics system
      disabled
      oneshot

开机 → init 起 advert（读 persist.sys.advert_enable）
     → 扫描 /data/data/com.pptv.launcher/ 下 4 个素材目录
     → 若开关为 1 且有素材/策略 → 全屏播放图片或视频 N 秒（策略里 duration=15）
     → 播完才进桌面
```

被读取的目录（`advert` 二进制里的字符串）：

| 路径 | 内容 |
|---|---|
| `/data/data/com.pptv.launcher/new_advert/` | 开机广告素材 `*.jpg`（1920×1080）+ `strategy.json` |
| `/data/data/com.pptv.launcher/new_advert_depressed/` | 同上（"压制版"，另一条策略分支） |
| `/data/data/com.pptv.launcher/shutdown/` | 关机广告图片 |
| `/data/data/com.pptv.launcher/shutdown_depressed/` | 关机广告图片（备选） |

`strategy.json` 关键字段（本例实测）：

```json
{"positionId":500074, "duration":15,
 "materialUrl":"http://asimgs.cp61.ott.cibntv.net/imgs/materials/2019/4/9/..."}
```

> 素材是**早就下发好、常驻在本地**的，所以断网并不会让广告消失 —— 必须删文件 + 关开关。

相关系统属性：

```bash
getprop persist.sys.advert_enable      # 1 = 开，本次改为 0
getprop persist.sys.advert_status      # 播放状态标志
getprop persist.sys.picadvert.exit     # 图片广告退出标志
getprop persist.advert.delay_counter   # 延迟秒数
```

## 2. 执行步骤（本次实际做的）

```bash
adb root

# ① 先看有什么（务必先备份到电脑！见第 4 节教训）
adb shell ls -l /data/data/com.pptv.launcher/new_advert
adb shell ls -l /data/data/com.pptv.launcher/new_advert_depressed
adb shell ls -l /data/data/com.pptv.launcher/shutdown
adb shell ls -l /data/data/com.pptv.launcher/shutdown_depressed
adb shell cat /data/data/com.pptv.launcher/new_advert/strategy.json

# ② 备份到电脑（不要只备份到电视 /data/local/tmp）
adb pull /data/data/com.pptv.launcher/new_advert ./backup/new_advert
adb pull /data/data/com.pptv.launcher/new_advert_depressed ./backup/new_advert_depressed
adb pull /data/data/com.pptv.launcher/shutdown ./backup/shutdown
adb pull /data/data/com.pptv.launcher/shutdown_depressed ./backup/shutdown_depressed

# ③ 关开关（重启后仍生效）
adb shell setprop persist.sys.advert_enable 0
adb shell getprop persist.sys.advert_enable       # 期望回显 0

# ④ 删素材（只删这 4 个目录的内容）
adb shell rm -rf /data/data/com.pptv.launcher/new_advert
adb shell rm -rf /data/data/com.pptv.launcher/new_advert_depressed
adb shell rm -rf /data/data/com.pptv.launcher/shutdown
adb shell rm -rf /data/data/com.pptv.launcher/shutdown_depressed

# ⑤ 重启验收
adb reboot
```

## 3. 验收

- 冷启动（拔插头再上电）→ 直接进桌面/HDMI，无全屏广告。
- `adb shell getprop persist.sys.advert_enable` → `0`
- 重启后确认目录没被重新拉取（`ls` 四个路径应为空或不存在）。

> **不要尝试**：`rm /system/bin/advert`、`pm disable com.pptv.launcher`（后者会废掉 HOME 键，见 07）。
> 开关为 0 时 advert 进程即使还在跑也不会出图，删二进制既危险又无必要。

## 4. ⚠️ 备份翻车教训（本次真实事故）

第一版备份命令是在 PowerShell 里这样写的：

```powershell
adb shell "cp -rp /data/data/com.pptv.launcher/ /data/local/tmp/advert_backup/$d/"
```

`$d` 被 PowerShell 当变量展开了（为空），结果：
1. `cp` 把**整个 88MB 的 com.pptv.launcher 目录**复制进了 `/data/local/tmp`；
2. 而真正要备份的 4 个广告目录当时以为"已备份"，**实际广告图在卸载/清理前就被删了**；
3. /data 一度被占满（used 2.0G / free 0）。

补救：`rm -rf /data/local/tmp/advert_backup`，然后删素材、重启，广告确实没了。
**结论：备份必须落到电脑（`adb pull`），且在删除前 `ls` 确认备份文件真的在本地存在。**
以后再遇到 `$` 出现在 adb shell 参数里，PowerShell 用单引号 `'...'` 或 ps1 文件传参。

## 5. 如果哪天广告回来了

1. 先查开关：`getprop persist.sys.advert_enable`（升级/恢复出厂会重置为 1）。
2. 再查目录是否被重新下发（联网后 advert 或推送服务可能重新拉素材）。
3. 开关置 0 + 清空四目录即可；若 `/data/data/com.pptv.launcher` 被重装，需重新 `pm enable`/`adb root` 后操作。
4. 想彻底断根，可把 `com.pptv.newtvad`（NewTvAd 广告 SDK）与 `com.pptv.push.service`（下发通道）一并禁用 —— 见 04 文档表三。
