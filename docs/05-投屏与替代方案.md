# 05 · 投屏方案：现实结论

需求：手机 / 平板 / 电脑 → 电视，**免费 + 无广告 + 协议齐全**（AirPlay / Miracast / DLNA 全都要）。

**结论先说：在 Android 5.0.1（API 21）+ armv7 的国产电视上，这个四全方案不存在。**
下面是逐个排除的记录，省得你再踩一遍。

---

## 1. 电视端现状（重要前提）

| 项 | 值 |
|---|---|
| Android | 5.0.1 / API 21（绝大多数新投屏 App 已要求 API 23+） |
| CPU | Cortex-A17 四核，**armv7**（许多新包只发 arm64） |
| 内存 | 2GB |
| 已有投屏类应用 | `com.pptv.playhelper` 投屏助手（系统预装）、`com.hpplay.happyplay.aw` 乐播投屏 8.18.38 |
| 系统级协议栈 | `pm list packages` 里**没有** Miracast/WFD/无线显示的系统包 |

> 没有系统级 WFD sink 包，意味着**Miracast 镜像**要么靠第三方 App 模拟，要么根本不支持。
> 想让 iPhone 镜像（AirPlay Mirroring）必须 App 实现 AirPlay 接收端，而这在 armv7 + API21 上选择极少。

## 2. 逐个候选与排除理由

| 方案 | 免费? | 广告? | 协议 | Android 5 / armv7 | 结论 |
|---|---|---|---|---|---|
| **幕桥 mubridge** v3.1 | 免费 | 无广告、无内购、无登录 | DLNA / UPnP / HTTP（**仅**） | ❌ 要求 **Android 6.0+**（API 23） | 系统版本不够，装不上 |
| **AirScreen** (`com.ionitech.airscreen`) | 名义免费 | ⚠️ 免费版**试用 1 小时后每 5 分钟弹购买页并中断播放** | AirPlay + Cast + Miracast + DLNA（最全） | ✅ 有 arm-v7a / minapi-21 变体 | **试用软件**，不是免费方案 |
| **AirPin STD/PRO "ad"** (`com.waxrain.airplayer*`) | 免费 | 名称里 `ad` = ad-supported，即**广告支持版** | AirPlay + DLNA + Miracast | ✅ 兼容 | 有广告，不符合"无广告" |
| **AirReceiver Lite** (`com.softmedia.receiver.lite`) 5.1.8 | 免费版有限制 | 实测**否决** | DLNA + AirPlay + Cast | ✅ 标称 Android 5.0+ | 实测体验不达标（广告/功能限制/稳定性），**不推荐** |
| **Kodi / VLC** | 免费开源 | 无 | ❌ 二者都不是 AirPlay/DLNA **接收端** | — | 方向错了，它们只做播放器 |
| 系统自带**投屏助手** (`com.pptv.playhelper`) | 免费 | 系统级，无明显广告 | 厂商实现的 DLNA/镜像（以实测为准） | ✅ 原生 | **最省事，优先用它** |
| **乐播投屏** (`com.hpplay.happyplay.aw`) | 免费 | 有广告/推广 | AirPlay + DLNA + 镜像，协议最全 | ✅ 已有可用版本 | 能用，但**有广告**，与目标冲突 |

## 3. 为什么"四全"做不到

1. **API 门槛**：AirPlay 接收端要处理 H.264 硬解 + 私有握手，主流实现（幕桥、新版乐播、AirScreen 新版）都把 minSdk 提到 23+。
2. **架构门槛**：armv7 的包在新版本里普遍停更，只剩旧的、带广告的版本。
3. **商业模型**：协议最全的实现（AirScreen、乐播、AirPin）都靠广告/内购变现；纯免费无广告的开源实现（幕桥）协议只做 DLNA/HTTP。
4. **系统限制**：没有 WFD sink，Miracast 镜像只能软解，2GB 内存 + Mali-450 上延迟和画质都难保证。

## 4. 推荐路线（按优先级）

### 路线 A：够用就行（推荐）
直接用**系统自带「投屏助手」**：
- 手机/电脑的 DLNA 投屏（视频 App 的"投到电视"、Windows 的"播放到设备"）可直接用；
- 不装任何新 App，零广告、零风险。
- 缺点：iPhone 镜像、完整 Miracast 镜像大概率不行。

### 路线 B：协议最全，接受广告
保留 **乐播投屏**（`com.hpplay.happyplay.aw`，本机 8.18.38 已在用）：
- AirPlay / DLNA / 镜像都能覆盖，是这台机器上**实际可用度最高**的选择；
- 代价是有开屏/推荐位广告，和"无广告"目标冲突，需要你自己权衡。

### 路线 C：愿意折腾（有风险，未验证成功）
1. 找 **AirScreen 的 arm-v7a / minapi-21 旧版 APK**（APKMirror 上有历史版本），
   但注意免费版 1 小时后每 5 分钟弹窗 —— 等于不可用。
2. 试 **幕桥的旧版本**（若有 API21 的构建）：只支持 DLNA/HTTP，功能有限但干净。
3. 想要真正干净的全协议方案，现实路径是**换电视/加一个电视盒子**（Android 9+ 的盒子几十到几百元，
   投屏生态完全不同），而不是在这台 2015 年的机器上死磕。

### 路线 D：非投屏替代
- 电脑 → 电视：HDMI 线（最稳，零延迟）。
- 手机 → 电视：电视装 Kodi/VLC 开 DLNA 服务器**反过来**让手机访问（不是镜像，是拉流播放）。

## 5. 实测建议流程

```bash
# 先看系统里到底有没有投屏相关包
adb shell pm list packages | grep -iE 'cast|mirror|wfd|dlna|airplay|lebo|hpplay|playhelper'

# 看投屏助手支持哪些入口（打开它的 Activity 列表）
adb shell dumpsys package com.pptv.playhelper | grep -E 'Activity|intent'

# 装第三方后验证是否真的在跑
adb shell dumpsys window | grep mCurrentFocus
```

验证要点：**用手机实际投一次**，看是否
① 有开屏广告 ② 投 10 分钟是否弹窗 ③ 镜像延迟是否可接受 ④ 声音是否同步。
只看应用商店截图和"支持协议"列表会严重误判（AirScreen 就是典型）。

---

## 6. 一句话总结

- 要**干净**：用系统投屏助手 + HDMI，放弃 iPhone 镜像。
- 要**全能**：用乐播，接受广告。
- 要**既干净又全能**：这台电视做不到，换盒子/换机是唯一现实解。
